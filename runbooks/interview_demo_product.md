# Interview demo product contract

## Purpose and claim boundary

This runbook freezes the interview-facing product before implementation expands. The product is a
visual demonstration of an **action-conditioned movement world model**: from one authoritative
Unreal character state, the system rolls candidate actions forward, selects an action, lets Unreal
determine the realized motion, and compares prediction with reality.

This is not a pixel-generating model, a general environment simulator, or evidence that the learned
residual controller is statistically superior. Only genuine rollout output may be drawn. Unreal is
authoritative for realized movement and collision outcomes. Prediction episodes `5301` and `5302`
remain sealed until the original recovery gates permit opening them.

The final recording is deliberately outside this runbook. This document prepares a deterministic
scene, controls, narration order, acceptance checks, and recovery path for the user to record.

## Frozen 75-second visual sequence

The target duration is 75 seconds, with a permitted range of 60--90 seconds. A scene may be shown
live or captured later, but its mode label must remain visible and truthful.

| Time | Screen action | What it proves | Spoken emphasis |
| --- | --- | --- | --- |
| 0--8 s | Show the character, target, obstacle/gate, compact HUD, and authoritative-state marker. | The model starts from a finalized Unreal observation. | "Unreal owns what actually happened; the model starts from that observed state." |
| 8--22 s | Hold one state and show four simultaneous forward, left, right, and stop futures. | The same state can be rolled forward under counterfactual action sequences. | "These branches share one source observation and differ by future action." |
| 22--36 s | Show the faint CEM candidate fan, then emphasize its selected path and first action. | Planning searches real model rollouts rather than following a scripted route. | "The planner scores alternatives, executes only the first action, then observes again." |
| 36--50 s | Advance through observe--plan--act cycles while the selected path updates and the yellow realized trail grows. | Receding-horizon control compares prediction with authoritative execution. | "Every new Unreal result replaces imagination as the source of truth." |
| 50--62 s | Overlay the blue nominal future and, only if schema/hash validation succeeds, the orange residual-corrected future for the same state and actions. | The learned component changes a bounded state-space prediction under a matched comparison. | "This is a learned correction to the nominal dynamics, not a claim of universal improvement." |
| 62--70 s | If reliable, apply the controlled sideways push; otherwise change the gate/target and show replanning. | The system responds after a change becomes observable. | "It cannot know an undisclosed future push; it replans after observing its consequence." |
| 70--75 s | Trigger or show the verified service-loss state and safe stop, then return to the final architecture view. | Failure does not authorize reuse of a late or stale command. | "A missing controller produces a safe stop, not invented control." |

If continuous MPC is not deadline-safe, replace the 36--70 second segment with deliberate single
steps. Do not omit or disguise the `STEPPED` label.

## Frozen visual language

| Element | Appearance | Meaning |
| --- | --- | --- |
| CEM candidates | Thin, translucent gray | Alternative futures generated by the active model |
| Selected trajectory | Thick white with a bright green endpoint | Highest-ranked trajectory for the displayed planning problem |
| Nominal prediction | Blue | Analytic/nominal dynamics rollout |
| Residual prediction | Orange | Nominal rollout plus learned residual correction |
| Realized Unreal trail | Yellow, solid and persistent within the episode | Collision-finalized motion that actually occurred |
| Target | Green marker/ring | Planner objective |
| Obstacle or timed gate | Red translucent geometry | Scene constraint, not model output |
| Current authoritative state | White ring or arrow at character root | Source state for the displayed prediction |
| Rejected/stale telemetry | Never drawn as a trajectory | It failed identity or freshness validation |

All trajectory colors must also have text labels so the comparison does not rely on color vision.
Paths need a small vertical offset to avoid z-fighting, but their horizontal positions must not be
artistically shifted. A reset, source-observation change, or controller switch clears predictions
that no longer match the displayed state.

## Mandatory mode labels

Exactly one of these labels must remain visible whenever predictions are shown:

- `PAUSED COUNTERFACTUALS — one finalized Unreal state; no actions executing` means execution is
  intentionally held while genuine futures are generated from one captured observation.
- `STEPPED MPC — plan, execute one action, reobserve` means the system intentionally waits for a
  completed planning step before advancing; it is not represented as continuous real time.
- `LIVE MPC — deadline-validated receding-horizon control` is allowed only when the displayed run
  uses the active deadline gate and no late action is knowingly applied.
- `OFFLINE REPLAY — recorded observations; Unreal is not being controlled now` means trajectories
  are regenerated or displayed from previously recorded states.

Optional residual status labels are `RESIDUAL VERIFIED` and `RESIDUAL UNAVAILABLE — nominal only`.
The former requires the expected checkpoint schema, feature order, normalization, and hash checks.
Never relabel an offline or stepped sequence as live in narration, captions, or packaging.

## Operator controls

The interview operator needs a small, deterministic control surface. Keyboard bindings may change
during implementation, but the visible control names and effects are frozen:

| Control | Effect | Safety rule |
| --- | --- | --- |
| `Reset Demo` | Reset the episode to its known anchor and clear paths/history. | The new episode cannot display or apply prior-episode state. |
| `Capture State` | Hold the latest finalized Unreal observation as the counterfactual source. | Display its episode and observation sequence. |
| `Show Branches` | Toggle forward/left/right/stop futures from the captured state. | All four branches use the same model, horizon, timestep, and source state. |
| `Show Candidates` | Toggle the CEM candidate fan and selected path. | Candidates must be planner output, not decorative splines. |
| `Step Plan` | Plan, authorize the first action if current, execute it, then wait for reobservation. | Reject stale identity or missed deadline. |
| `Run/Stop MPC` | Start or stop repeated planning in the permitted live/stepped mode. | Stop produces zero/safe control and keeps the mode label truthful. |
| `Nominal/Residual` | Toggle or overlay matched nominal and residual predictions. | Switching cannot change source state/actions for a comparison. |
| `Apply Push` | Apply the predefined sideways disturbance once. | Use only after the pre-push prediction is visible; claim replanning, not foresight. |
| `Safe-stop Check` | Stop controller responses or use the supported failure control. | Restore service only through the documented recovery path. |
| `Clear Paths` | Clear visualization without changing simulation state. | Must not alter planner/controller history. |

The operator should be able to complete the sequence using `Reset Demo`, `Capture State`, `Show
Branches`, `Show Candidates`, `Step Plan` or `Run MPC`, optional `Nominal/Residual`, and optional
`Apply Push`. Developer/log controls must stay out of the presentation view.

## HUD contract

The compact HUD shows only information that can be traced to runtime telemetry:

- mode label;
- active rollout model and residual verification status;
- episode and source-observation sequence;
- horizon, timestep, and candidate count;
- chosen action;
- planning and end-to-end latency, without substituting simulation time for wall time;
- prediction error only after a matching Unreal outcome exists;
- service health, deadline/fallback status, and safe-stop state.

Unavailable values render as `N/A`, not zero. A prediction may not retain a healthy/current label
after its source observation is superseded.

## Scope by priority

### Tier 1 — must ship

- One readable Unreal scene with character and target.
- One authoritative captured state and four genuine counterfactual branches.
- Genuine CEM candidates, selected future, and selected first action.
- Separate predicted and realized paths with episode/sequence provenance.
- Truthful paused, stepped, live, or offline mode label.
- Reset clearing, stale-action rejection, and safe-stop behaviour remain enabled.
- Compact HUD, fresh-launch procedure, relevant automated tests, and a rehearsable sequence.

### Tier 2 — strongly desired

- Repeated observe--plan--act--reobserve movement toward the target.
- Matched nominal-versus-residual overlay using the validated existing checkpoint.
- Readable timed gate or obstacle and polished presentation camera.
- Prediction-error display derived from a matching authoritative transition.

### Tier 3 — stretch only

- Controlled push and visible post-observation recovery.
- Deadline-validated continuous live MPC if stepped mode is the safe baseline.
- Animation polish, advanced toggles, and additional scenarios.

Tier 3 is removed before compromising Tier 1 authenticity, safety, or clarity. A nominal-only or
stepped product that is labelled accurately is acceptable; fake residual improvement or stale live
control is not.

## Acceptance checks

### Authenticity and provenance

- [ ] Forward, left, right, and stop paths share an identical episode, source sequence, state,
      model, horizon, and timestep; only the candidate future actions differ.
- [ ] At least one displayed path can be reconstructed from the serialized rollout values within
      the documented numeric/coordinate tolerance.
- [ ] CEM candidate and selected paths come from the planner output used for selection.
- [ ] Nominal and residual overlays, if shown, use the same source state and action sequence.
- [ ] Yellow realized points come only from later finalized Unreal observations in the same episode.

### Lifecycle and timing

- [ ] Reset clears predictions, realized trail, pending action, and model/controller history as
      specified; no prior-episode visualization reappears.
- [ ] A superseded observation cannot authorize an action or remain marked current.
- [ ] Service loss produces the existing safe-stop path.
- [ ] Planning and end-to-end wall-clock latency are labelled separately from simulation time.
- [ ] `LIVE MPC` is shown only after its deadline condition passes; otherwise `STEPPED MPC` remains
      visible.

### Visual comprehension

- [ ] A viewer can identify current state, alternatives, selection, and reality without source code.
- [ ] The legend remains readable at the intended recording resolution.
- [ ] Candidate density does not obscure selected, nominal/residual, or realized paths.
- [ ] The sequence communicates observe -> imagine -> choose -> execute -> compare -> replan.

### Claim discipline and readiness

- [ ] No claim implies a pixel/general world model or statistical residual superiority.
- [ ] Prediction episodes `5301` and `5302` remain unopened.
- [ ] The product launches from the documented clean procedure and has an offline fallback.
- [ ] Relevant Python, lint, diff, and available Unreal checks pass before handoff for recording.
- [ ] The user can deliver the movement/runtime and causal/ML explanations below without reading.

## Interviewer-specific talking points

### Daniel: movement, animation, and runtime engineering

> "Unreal is authoritative for finalized motion and collisions. I convert that state into the
> planner's coordinate frame, roll candidate controls through short-horizon dynamics, execute only
> the first selected action, and reobserve. Every message carries episode and sequence identity, so
> a reset, late reply, or service failure cannot silently reuse an old command. The colored paths
> visualize that real lifecycle; they do not replace it."

Be ready to point at acceleration/deceleration, facing and velocity state, coordinate conversion,
the first-action MPC policy, reset clearing, wall-clock deadlines, stale rejection, and safe stop.
Do not claim the visualization proves animation quality or full collision prediction unless those
properties are separately measured.

### Viktoriia: causal ML, robustness, and evaluation

> "This is a deliberately scoped state-space world model: it predicts decision-relevant character
> motion conditional on proposed actions. The branch view is an intervention on future actions from
> one observed state. The learned residual corrects nominal dynamics but is compared using the same
> state and actions. Unreal supplies the outcome; the model does not grade itself. An undisclosed
> future push is not predictable, so the valid claim is recovery after its effect is observed."

Be ready to distinguish conditioning from causal identification, recursive rollout from one-step
teacher forcing, validation selection from sealed final evaluation, prediction quality from control
benefit, and a qualitative matched example from statistical superiority. The demo establishes an
integrated, inspectable prototype; the deferred locked paired study is required for a population-
level performance claim.

## Handoff for manual recording

Before the user records, provide the exact launch commands, level, camera transform, binding list,
mode choice, expected HUD values, and recovery steps confirmed on that build. Also provide a short
offline fallback that carries the `OFFLINE REPLAY` label. Do not make the final recording part of an
automated acceptance test; the product and its evidence must pass before recording begins.
