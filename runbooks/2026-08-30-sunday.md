## Today's single objective

Prove that a version-matched Unreal character can accept programmatic desired-velocity commands, expose authoritative post-movement state, reset without cross-episode state leakage, execute a deterministic timed gate, and write one valid episode.

Today is not a model-training day. No residual MLP, CEM integration, AnimGen work, or visual polish begins before the feasibility gate passes.

## Concepts the candidate must own today

### Desired velocity

The command specifies the velocity the movement controller should move toward, not a teleport and not necessarily the velocity achieved immediately. Acceleration, deceleration, turning, smoothing, collision, and controller state determine the executed motion.

Candidate must explain:

- input units and coordinate frame;
- where magnitude is clamped;
- how long the command is held;
- why desired velocity is a useful two-dimensional planning action;
- why requested and executed velocity differ.

### Authoritative state

The actor/capsule/Mover simulation state determines gameplay motion and collision. The rendered animation root may deliberately differ. Planning must use one stable source rather than mixing actor and animation transforms.

Candidate must explain:

- exactly which object/component owns position and velocity;
- at what tick phase the state is sampled;
- why animation root is diagnostic rather than planning truth;
- units and local/global frame for every field.

### Deterministic reset

A reset must restore all state that can affect the next episode: transform, velocity, controller/Mover hidden state where possible, gate phase, target, counters, IDs, history, and planner warm start. Same seed and actions should reproduce the same initial condition and schedule.

Candidate must explain why resetting only the visible actor transform is insufficient.

### Episode-safe protocol

Every observation/action carries a protocol version, episode ID, and sequence number. These fields prevent a delayed action from an old timestep or previous episode from controlling the current character.

Candidate must explain stale-sequence rejection and why Unreal clamps the returned action even when Python already clamps it.
